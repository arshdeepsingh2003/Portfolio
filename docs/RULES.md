# Project Rules

## Product and design rules
1. Keep Web Development Projects and Data Analytics Projects visibly separate.
2. Use the palette and design principles in `DESIGN_SYSTEM.md`.
3. Use real screenshots, real links, and owner-approved descriptions.
4. Never invent metrics, client names, testimonials, or achievements.
5. Avoid copying the reference website's colors or exact visual structure.
6. Favor readability, whitespace, and small purposeful details over decoration.

## Engineering rules
1. Inspect existing files before editing.
2. Reuse current dependencies and patterns.
3. Keep components small and single-purpose.
4. Keep content separate from layout where practical.
5. Do not add a backend, database, authentication, or CMS without a requirement.
6. Never put secrets in frontend code or commit `.env` files containing secrets.
7. Preserve accessibility, responsive behavior, and reduced-motion support.
8. Do not claim tests, builds, or link checks passed unless actually run.
9. Do not make unrelated changes.
10. Update documentation when a decision or behavior changes.

## Content and privacy
- Do not publish private company data, internal dashboards, credentials, customer details, or work prohibited by an NDA.
- Use anonymized/demo data when a screenshot is needed and approved.
- Do not expose personal contact details beyond the contact methods the owner chooses to publish.
